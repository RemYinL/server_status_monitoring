# 01 需求分析

## 1. 背景与设备环境

| 角色 | 设备 | 说明 |
|---|---|---|
| 开发机 | Windows 笔记本（含 WSL，依赖已安装） | 全部开发与全栈调试在本机完成 |
| 被监控对象 | 一台 Linux 服务器 | 经 Tailscale 组网，可 SSH；有公网域名；当前离线，待抵达后部署 |
| 告警/查看终端 | iPhone 16 Pro | Bark 接收告警；小组件查看实时状态 |
| 穿戴设备 | 小米手环 11 NFC | 通过 iPhone 通知同步震动接收告警 |

## 2. 功能需求（按优先级）

### F1 在线状态监控（P0）
- 服务器 agent 以固定周期（默认 30s，可配置）上报心跳数据包至中转端。
- 中转端超过阈值（默认 90s）未收到心跳 → 主动向服务器发起握手探测，连续 3 次失败 → 判定离线。
- 判定离线后向 iPhone 发送 Bark 告警（手机弹窗 + 手环震动）。
- 服务器恢复后发送恢复通知。

### F2 基础资源指标（P0）
- 随心跳上报：CPU 使用率、内存用量、磁盘用量（指定挂载点）、系统负载、运行时长、网络吞吐（可选）。

### F3 关键服务存活（P1）
- 监控目标：网站生产前端（HTTP 探针）、Tailscale 隧道（tailscaled 状态 + ping 对端）、可扩展的进程/端口探针。
- 任一关键服务连续 N 次（默认 2 次）探测失败 → 即时告警（不等待离线判定）。

### F4 日志告警（P1）
- 采集 journald 指定 unit 与指定日志文件，按正则规则匹配（如 ERROR、OOM、segmentation fault）。
- 命中规则即作为告警事件随上报发送，支持去重与限频（同一规则 5 分钟内只报一次）。

### F5 关键项目代码变动（P2）
- 跟踪指定 git 仓库的 HEAD commit、分支、工作区脏状态。
- HEAD 变动时上报变更事件（commit hash、作者、摘要）。

### F6 状态可视化（P1）
- iPhone 小组件（Scriptable）定期拉取中转端最新状态快照，展示：在线/离线、核心指标、关键服务状态、最后心跳时间。

## 3. 非功能需求

| 类别 | 要求 |
|---|---|
| 资源占用 | agent 常驻内存 < 50MB，CPU 常态 < 1% |
| 可靠性 | 网络抖动不触发误报（超时阈值 + 多次握手确认）；agent 崩溃由 systemd 自动拉起 |
| 安全性 | 上报通道走 Tailscale 内网或 HTTPS + 共享密钥签名；Bark key 等机密走环境变量/配置文件（600 权限），不入库 |
| 可配置 | 采集周期、探针列表、告警规则、Bark 端点全部配置文件驱动（TOML） |
| 可维护 | Rust workspace 多 crate；协议结构体单一来源（common crate）；日志用 tracing |
| 可交付 | 一键部署脚本 + systemd unit；README 含完整部署步骤 |

## 4. 约束与边界

1. **iOS 平台限制**：iPhone 无法运行 Rust、App 无法常驻后台维持长连接。因此「服务器直推手机」改为「服务器 → 中转端 → Bark/APNs → iPhone」，功能等价且符合平台规范。
2. **中转端位置**：开发期跑在 Windows 笔记本（WSL）上；服务器抵达后可与 agent 同机部署（agent 自监控场景下，离线判定依赖 Tailscale 可达性，文档中说明该部署形态的风险与缓解）。
3. **误报控制**：离线判定必须经过「心跳超时 + 3 次握手失败」双重确认，任何一步恢复即取消告警流程。
4. **数据不出私域**：状态数据仅经 Tailscale 内网与 Bark 推送（告警文本不含敏感指标明细，仅摘要）。
